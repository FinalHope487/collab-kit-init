# 程序：委派

觸發：要把工作交給 fork 或子代理（本檔統稱子代理）。
讀者：agent。
審查怎麼交、額度、不可用時的退路：`docs/cold-review.md`。

委派子代理的 prompt 必須逐項寫明這五項，缺一不可：

| # | 欄位 | 寫什麼 |
|---|---|---|
| 1 | 目標 | 這一輪要交出什麼，用 user 的話寫 |
| 2 | 可改範圍 | 准許動的路徑，逐條列出 |
| 3 | 不可碰範圍 | 禁止動的路徑與具體值，逐條列出 |
| 4 | 驗收條件 | 清楚給出系統不變量或公開契約標準：例如「核心計算符合邊界驗收條件」、「公開 API 契約測試通過」、「既有回歸測試全綠」；屬探索／純視覺微調者寫明免新測試但既有測試維持綠 |
| 5 | 回報格式 | `完成項 / 未完成項 / 邊界衝突` |

- 子代理 優先選用適合其任務規模的高性價比模型，不論主模型為何
- 使用 子代理 前先確認額度，若額度有任何可能在工作期間耗盡就不派
- 子代理 碰到需要拍板的事回報給你，由你彙整進 `QUESTIONS.md`；它不自己決定、不直接問 user
- 子代理 回報完成後，自己跑一次驗證（測試或 diff）才可以轉述；不一致時以你的驗證為準，並指出報告哪裡不實
- 不傳送訊息給已結束的子代理（快取已釋放，續傳成本高），後續修改由主流程接手；只有整份要砍掉重做時才開全新的子代理
- 交給另一個 agent 工具時同樣適用本檔，且只有 `docs/project-rules.md` 明列該工具與授權範圍才可用；沒列就當作沒有這個工具
- 給照步驟做的 子代理 的交接文件用受控、簡單、祈使句的寫法，一句一個指令（`AGENTS.md`〈撰寫文件〉）
