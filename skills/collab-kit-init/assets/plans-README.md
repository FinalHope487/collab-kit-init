# 實作計畫

短計畫寫在 ROADMAP.md 待辦的〈怎麼做〉。跨模組、跨輪、有遷移或有明確步驟依賴時，建立本目錄下的 YYYY-MM-DD-<slug>.md，由同一欄連過來。

每份計畫使用以下章節：

1. **目標與狀態**：連到規格及本輪驗收條件。狀態填進行中、完成或取消。
2. **改動邊界**：列涉及的模組、資料和公開介面。
3. **步驟與驗證**：依序列出動作、依賴、驗證方式和通過條件。
4. **切換與回退**：有遷移、發布或相容性成本時填寫。
5. **結案**：只寫狀態改成完成或取消的那一行；取消時寫原因及接替計畫。實跑結果寫在 commit message，不寫回計畫。

技術方案或順序變動時更新計畫。若要改公開契約或驗收，先確認需求變更並更新規格。長期決策寫一行到 DECISIONS.md。

其他檔指向計畫時寫路徑加步驟編號，不抄內容。步驟編號不改、不重用。待辦的狀態只寫在 ROADMAP.md。計畫結案後，把仍生效的約束搬進 STATE.md 或 docs/spec.md；計畫檔何時搬走照 `docs/procedures/chores.md`，不在任務結尾做。
